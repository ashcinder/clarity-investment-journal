# 澄明 · 完整理财账本

React + TypeScript 前端，Node.js + SQLite 独立后端；同时保留已发布网站使用的 Cloudflare D1 后端。两种运行方式共享资产计算、交易日历、定投和数据校验逻辑。数据真正保存在数据库中，不依赖浏览器缓存。

项目位于 `/Users/tangyucinder/开发/现代化理财`，采用 npm workspaces，前后端各有自己的 `package.json`、启动命令和配置：

需要 **Node.js 22.18+**（建议 24 或更新版本）。首次在项目根目录安装依赖：


这会同时启动两个独立进程：

- **后端 API：http://127.0.0.1:4318/api/health**

前端将 `/api/*` 代理给后端，后端不托管网页。原来的 `4318` 现在是纯 API 地址，使用网页请打开 `5173`。

```bash

```


构建后运行：根目录执行 `npm run local` 会构建前端并同时启动前端预览和后端；已有构建时执行 `npm start`。也可分别在 `frontend/` 执行 `npm run build && npm start`，在 `backend/` 执行 `npm start`。

macOS 可双击 **启动理财账本.command**。按 `Ctrl+C` 停止。`npm run local:dev`、`npm run local:build`、`npm run local:start` 保留为兼容命令。

本地服务无需 Cloudflare 账户、ChatGPT 登录、API Key 或手动建表。首次本地账本为空，先创建账户再添加资产。

数据库位于 **`backend/data/clarity.sqlite`**。原 `.data/` 已原样迁移，数据内容不变。运行期间可能有 `-wal` 和 `-shm` 文件；建议通过界面导出 JSON，复制数据库文件前应停止后端。

可在根目录启动时设置 `CLARITY_PORT`（后端）、`CLARITY_FRONTEND_PORT`（前端）和 `CLARITY_DB_PATH`（数据库绝对路径）。单独启动前端时，`CLARITY_API_URL` 可指定后端地址；自定义前端端口时，还需给后端设置 `CLARITY_FRONTEND_ORIGIN`。更多说明见 `frontend/README.md` 和 `backend/README.md`。

前后端默认只监听本机，用于单用户个人账本。线上使用 Sites 登录与 D1；本地和线上数据独立，可通过 JSON 导入/导出迁移。

## 自定义账户图片

在“账户与资产 → 编辑账户”（或新建账户）中点击“上传图片”，也可以把一张本地图片拖到图标或上传区域，区域高亮后松开。预览后点击“保存账户”。支持 PNG、JPG、WebP、SVG，原图最大 5 MB；可以更换图片或恢复默认图标。图片显示在账户卡片、账户详情、定投计划和流水中。

SVG 上传后通过浏览器的独立图片上下文转换为静态缩略图（不保留动画或依赖外部资源的内容），不会把 SVG 源码插入页面。只有 viewBox 的 SVG 图标也支持；保存和备份使用与其他格式一致的缩略图。

图片在浏览器中缩为 128 × 128 缩略图，完整保留内容，优先保留透明背景（不支持 WebP 编码时使用白色背景）；不保存原图。每张缩略图的 data URL 最多 12,000 字符，作为小型账户配置随账本一起持久保存，JSON 备份、导入和本地 / 云端版本都支持。已有账户无需迁移，未设置图片时沿用分类图标。清空数据时选择“保留账户”也会保留账户图片。

## 账户里面直接是资产

一个账户可以有多个资产，例如同一美元账户内的 BTC、ETH、SPY 和网格仓位。账户类别作为默认资产类型；每项资产可以指定自己的类型，资产配置图按资产类型归类。

日常录入只需 **资产名称、累计投入金额、收益率**。资产类型默认跟随账户，用于配置比例图；无需填写代码、币数 / 份额、成本单价、当前价格或杠杆。币种由账户决定，直接显示在金额标签中。

- 收益金额 = 累计投入金额 × 收益率。
- 当前价值 = 累计投入金额 + 收益金额 − 历史取出金额（如有）。
- 例如投入 1,200 USD、收益率 10%，收益 120 USD，当前价值 1,320 USD。
- 网格也只填写实际投入本金 / 保证金及收益率，不将杠杆名义仓位计入总资产。

在“账户与资产 → 进入账户”添加、编辑或删除资产。资产列表只显示名称、投入、收益金额、收益率和当前价值。已有记录中的投入与收益自动带入简化表单，历史数量、价格及流水继续保留；保存会新增日期化本金更正与估值，避免把全部本金重复记成一次投入。存在账户未分配资金时，可以选择用它作为本金来源。

新建或通过简化表单保存的资产使用金额记录模式。自动定投会增加投入本金和资产价值，不按旧价格猜测份额；新增本金本身不产生收益，因此定投后收益金额保持、累计收益率重新计算，用户可再手动更新收益率。旧版数量记录的计算逻辑仍兼容，不影响历史备份。

删除资产会移除其记录与定投，其价值从总资产扣除；其他资产保留。修改持仓形成日期化估值和本金更正记录，避免把整个持仓金额重复当成一次新投入。账户归档可保留历史；空账户可删除。

## 清空测试数据

打开 **偏好设置 → 清空数据**：

- 保留账户，只清空资产、流水、定投计划、手记；或
- 全部清空，包括账户。

输入 **清空** 才能执行，弹窗内提供“先下载备份”。清空保留汇率和已核验交易日历，删除自动定投计划，之后不会再生成测试投入或恢复示例数据。此按钮不会自行执行，需要你在界面操作。

## 自动定投和多币种

所有计划统一使用北京时间（UTC+8）。支持每日、周一至周五、每周、每月和市场交易日；Crypto 每日包括周末，基金和美股按对应市场的交易日历排除休市。每月 29–31 日在短月按月末处理，周/月计划休市顺延。未知年份停止生成该市场的记录，须先更新日历。

计划可指定具体资产，并独立选择 USD / CNY。入账时用该日期账本汇率换算为账户原币，历史流水保留汇率和原始计划金额说明。前端可同时查看 USD、CNY 总额。

自动模式按预设金额入账，无需逐笔操作；也可切换手动确认。**自动记账不代表券商实际成交**。金额模式只累计投入，收益率由用户按实际情况更新；旧版数量模式继续兼容原有估算记录。

本地后端运行期间每分钟处理到期计划，浏览器关闭也可记账；后端停止期间下次启动或访问时补齐。线上版打开/同步时补齐。重复访问不会重复入账，删除一笔自动流水会将该期标记为跳过。

## 后端 API

所有业务 API 在 `backend/` 中；根目录 `app/api/` 只将线上请求转发到 `backend/cloud/routes/`。前端不会导入数据库或后端服务代码。`shared/ledger.ts` 为前后端共用的纯计算模块。

独立后端 API：

| 方法 | 路径 | 功能 |
| --- | --- | --- |
| GET | `/api/health` | 本地运行状态 |
| GET | `/api/ledger` | 读取账本并补记到期定投 |
| PUT | `/api/ledger` | 保存完整账本，参数 `{state, revision}` |
| POST | `/api/reset` | 清空，参数 `{revision, confirmation: "清空", keepAccounts: true/false}` |
| GET | `/api/fx` | 获取 USD/CNY 参考汇率 |

保存与清空都使用版本号防止覆盖较新的数据；来源校验、金额和引用校验在后端执行。SQLite 启动时自动建表，线上 D1 通过迁移建表。请不要修改已应用的 `drizzle/0000_funny_tombstone.sql`。

## 数据口径和边界

- 收益 = 当前价值 + 累计取出 − 累计投入；回报率为简单累计收益率，不是年化或时间加权收益。
- 曲线来自真实录入、估值与计划记录，不伪造市场历史。旧估值沿用至下一次更新。
- [Frankfurter](https://frankfurter.dev/) 提供每日参考汇率；离线时可手动设置。
- [上交所 2026 休市公告](https://www.sse.com.cn/disclosure/announcement/general/c/c_20251222_10802507.shtml) 和 [NYSE 日历](https://www.nyse.com/trade/hours-calendars) 为现有市场日历来源。未建模单只基金暂停申购、临时停市或提前收盘。
- 未连接交易所、券商执行交易，也没有自动获取资产价格；收益率由你按实际情况更新。
- 上限：100 个账户、500 项资产、100 个计划、10,000 条流水、5,000 篇手记，JSON 备份 4 MB。用于个人账本。
